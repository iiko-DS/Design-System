# Мобильная версия в iiko DS — сводка

> Руководство по архитектуре переменных для десктоп/мобайл и тем.

## План действий по шагам

### Этап 0. Подготовка (решения до работы)
- [ ] Зафиксировать брейкпоинт: **768px** — граница desktop → mobile.
- [ ] Договориться: **планшет = мобильные компоненты + отдельная компоновка** (не третий набор).
- [ ] Договориться: **дефолтный режим = Desktop**.

### Этап 1. ДС — переменные в Figma
- [ ] Открыть коллекцию **`Component`** → добавить режим **`Mobile`**.
- [ ] Пройти по переменным: отметить **размерные** (отличаются) и **общие** (цвет/радиус/тень).
- [ ] Проставить мобильные значения **только для отличающихся** (`Banners/*`, `Button/*`, `Input/*` и т.д.).
- [ ] Общие переменные **не трогать** (держать алласами на один примитив).
- [ ] Тема — **отдельная коллекция `Color`** с режимами `Light`/`Dark` (идёт независимо).

### Этап 2. Компоненты
- [ ] По каждому компоненту определить категорию: **только значения → режим**, **структурно другое → отдельный компонент**.
- [ ] Проверить каскад: встроенные инстансы (кнопка в баннере) подхватывают режим.
- [ ] Структурные `_mob`-компоненты оставить как есть.
- [ ] Убедиться, что **все размерные переменные — в одной коллекции** (иначе каскад не сработает).

### Этап 3. Экран
- [ ] Выбрать экран, заменить десктоп-инстансы на мобильные.
- [ ] **Перекомпоновать лейаут**: сайдбар → бургер/низ, шапка с табами, степпер, форма, футер.
- [ ] Собрать планшетную и телефонную сетку (брейкпоинты внутри мобильного диапазона).

### Этап 4. Код (CSS)
- [ ] Вынести захардкоженные размеры компонентов в **токены**.
- [ ] Создать **`modes.css`** — `[data-mode="mobile"]` с переопределениями размера.
- [ ] Создать **`themes.css`** — тема (`data-theme`).
- [ ] Порядок подключения: `tokens.css` → `modes.css` → `themes.css`.
- [ ] Прописать соглашение в **`iiko-ds-spec.md`** (см. раздел 13).

### Этап 5. Проверка
- [ ] В Figma: переключить режим → обновляются все компоненты и вложенные инстансы.
- [ ] В коде: переключить `data-mode` → всё каскадится, вложенные тоже.
- [ ] Старые прототипы не сломались (дефолт = десктоп).

---

## 1. Две независимые оси

| Ось | Что меняет | Пример |
|---|---|---|
| **Theme** | только **цвет** | `#333` ↔ `#fff` |
| **Mode / Platform** | только **размер/паддинги/шрифт** | кнопка 36 ↔ 44 |

Цвет от платформы не зависит, паддинги от темы не зависят → **не перемешивать** в одной переменной.

## 2. Три уровня токенов

1. **Примитивы** — `--ds-size-*`, `--ds-palette-*` (готово).
2. **Семантические** — `--ds-color-button-*`, `--ds-color-text-*` (готово).
3. **Компонентные токены размера** — добавить, управляются осью Mode.

```css
:root {
  --ds-button-height-m: var(--ds-size-9x);        /* 36 */
  --ds-button-pad-y-m: var(--ds-size-2x);         /* 8px */
  --ds-button-pad-x-m: var(--ds-size-3x);         /* 12px */
}
```

## 3. Цвет — общий, размер — на режим

- Цветовые токены (`--ds-color-banners-*`, `--ds-color-button-*`) **общие** для десктопа/мобилы.
- Размер/паддинги — **свои на режим**.
- Отдельные мобильные токены цвета **не нужны** — привязываются один раз.

## 4. Как это делается в Figma

- Режим **`Mobile` создаётся у коллекции переменных, а не у компонента**. У нас — коллекция **`Component`**.
- При добавлении режима значения **копируются из дефолтного**. Меняете **только отличия**.
- **Не стирать/не очищать** совпадающие значения — у переменной всегда есть значение в каждом режиме; «пустого режима» не бывает.
- Чтобы совпадающие значения не были «дублями» — держите их **алласами на один примитив**, а не хардкодом.

## 5. Banner — конкретный пример

Переменные в коллекции `Component`:
`Banners/Pad top/left/right/bottom`, `Banners/Text size`, `Banners/Text size tip`, `Banners/Horizontal/Gap`, `Banners/Vertical/Gap`, `Banners/Text color`, `Banners/Border color`, `Banners/Border radius`.

Сейчас в `banner.css` захардкожено: `padding 12px 16px`, `font 14px/20px`, `gap 8px`, `radius 12px`.

**Правильно:** вынести в токены, дефолт = десктоп, `[data-mode="mobile"]` переопределяет только отличия; цвет/радиус не трогать.

```css
:root {
  --ds-banner-pad-top: var(--ds-space-3x);
  --ds-banner-pad-right: var(--ds-space-4x);
  --ds-banner-pad-bottom: var(--ds-space-3x);
  --ds-banner-pad-left: var(--ds-space-4x);
  --ds-banner-gap: var(--ds-space-2x);
  --ds-banner-font-size: var(--ds-typography-body-font-size-s);   /* 14 */
  --ds-banner-radius: var(--ds-radius-3x);
}
[data-mode="mobile"] {
  --ds-banner-pad-top: var(--ds-space-4x);
  --ds-banner-pad-right: var(--ds-space-5x);
  --ds-banner-pad-bottom: var(--ds-space-4x);
  --ds-banner-pad-left: var(--ds-space-5x);
  --ds-banner-font-size: var(--ds-typography-body-font-size-m);   /* 16 */
  /* кнопка внутри подхватит мобильный размер из этого же блока */
  --ds-button-height-m: var(--ds-size-11x);  /* 44 */
}
```

> Значения мобильных паддингов/шрифта — **плейсхолдеры**, брать из режима `Mobile` в Figma, не выдумывать.

## 6. Встроенные инстансы (кнопка в баннере)

Кнопка внутри баннера становится мобильной **автоматически**, если её размерные переменные (`Button/Height M` и т.п.) лежат **в той же коллекции `Component` с тем же режимом `Mobile`**. Отдельно прописывать её не нужно.

> ⚠️ Работает, только если **все** размерные переменные компонентов живут в **одной общей коллекции с режимами**. Иначе каскада не будет → **одна общая размерная коллекция на всю ДС**.

## 7. Ограничение Figma: режим глобальный

- Режим — **глобальный на файл**, не привязан к фрейму. «Мобильный» вид = активный режим коллекции, а не метка фрейма.
- **Оба баннера рядом одновременно не показать** переключением режима.
- Чтобы видеть десктоп и мобилу бок о бок (как на странице спецификации) → **per-instance override** либо **отдельные переменные на платформу** (`Banners/Pad top · Desktop` и `· Mobile`).

## 8. Сложный экран («Метро») vs простой (Banner)

- **Banner / Button / Input / Toggle** — отличаются **только значениями** → кандидаты на **режим**, а не на отдельный компонент.
- **Сложный экран** меняется **по структуре** (сайдбар, шапка с табами, степпер, футер не влезают) → нужна **перекомпоновка лейаута**, а не только смена размеров. Режим это не сделает.

## 9. Что это значит для `_mob`-компонентов

- **Не зря** — нужны сейчас, пока режимы не готовы, и навсегда для **структурно разных** компонентов.
- **Группа 1** (отличаются только числами) → временный инструмент, потом **сольются в режим**.
- **Группа 2** (отличаются структурой) → остаются отдельными компонентами.

Правило: *одинаковый набор свойств/цвет/радиус/состояния, отличаются только числа → Группа 1 (режим). Меняется состав/порядок → Группа 2 (отдельный компонент).*

## 10. Планшет

- **768px** — брейкпоинт «десктоп → мобильная вёрстка».
- Планшет и телефон используют **один мобильный набор компонентов** (тач-эргономика одинаковая).
- Отличает их **компоновка**, а не компоненты:
  - телефон: 1–2 колонки, узкий контейнер, бургер/низ;
  - планшет: 2–4 колонки, шире контейнер, свёрнутые иконки (как в десктопе).
- Третий «планшетный» набор компонентов **не нужен** — это лейаут-брейкпоинты внутри мобильного диапазона.

## 11. Глазами разработчика

- **Одна и та же разметка** для десктопа и мобилы, без `--mobile`-классов.
- Переключение — **`data-mode="mobile"` + `data-theme="dark"`** на корне (или `@media`).
- Значения — из токенов + `iiko-ds-spec.md`.
- Чего **не делать**: `--mobile`-модификаторы, `style="height:44px"`, отдельные «мобильные» подмножества компонентов.

## 12. Практические нюансы внедрения

- `tokens.css` **генерируемый** → `[data-mode]`-блоки нельзя дописывать от руки. Варианты:
  - отдельный **`modes.css`** (+ `themes.css` для темы), подключаемый после `tokens.css`;
  - либо доработать экспортёр, чтобы выводил режимы в `[data-mode]`.
- **Порядок подключения:** `tokens.css` → `modes.css` → `themes.css`, чтобы каскад/специфичность были предсказуемы.
- Старые прототипы (`Prototype-Guide/*.html`) без `data-mode` будут в дефолтном (десктопном) виде — ок, дефолт = десктоп.

## 13. Что зафиксировать в `iiko-ds-spec.md`

> **Режим платформы** — атрибут `data-mode` на корне экрана (`desktop`|`mobile`), **тема** — `data-theme` (`light`|`dark`). Разметка компонентов от этого **не зависит** — классы одни и те же. Мобильные модификаторы (`--mobile`) **не создавать**. Размеры меняются только через токены в `modes.css`. Цветовые токены общие для платформ.
