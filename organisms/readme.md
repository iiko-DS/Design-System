# organisms — организмы дизайн-системы

Крупные сквозные блоки интерфейса приложения:

- `app-header/` — шапка приложения (вставляется в кадр сама);
- `app-sidenav/` — боковое меню L1 + L2 (состав правится в одном месте — объект `MENU`
  в `app-sidenav.js`; инструкция и демо стенд — внутри папки).
- `app-right-panel/` — правая панель: карточка Card (Type=Shadow) как каркас (шапка с заголовком
  и крестиком, скроллящийся контент, опциональный подвал; ширина — по контенту; затемнение — Backdrop).
- `app-header-content/` — шапка раздела: стрелка назад, подпись + заголовок, слот «После заголовка»
  (статус и/или дополнение), поиск и действия.
- `app-table-header-actions/` — полоса над таблицей: заголовок (или счётчик выбранного), слот
  «После заголовка» (разделитель + тумблер), действия справа.
- `app-page-footer/` — подвал страницы и таблицы: полоса с разделителем и слотом — итоги
  и кнопки (в «пустом» виде — подвал с одними кнопками).
- `app-table-card-adaptive/` — универсальная карточка таблицы для адаптива: строка таблицы
  превращается в карточку (работа пальцем, тач-нажатия).

Формат блока (эталон — `app-sidenav/`): **папка = один организм**, внутри `<имя>.css` + `<имя>.js`
(ассеты считаются от расположения скрипта — работают с любой страницы), `readme.md`
(назначение, подключение, правила), `demo.html` — **демо стенд** (страница проверки всех
состояний блока), свои ассеты.

Проверочные страницы компонентов, молекул и организмов ДС называем одинаково — **демо стенд**
(файл `demo.html`): сразу понятно, что это стенд для проверки, а не макет или страница-прототип.
У каждого блока — **свой `demo.html`** в его папке: файл самодостаточный и правится независимо
от стендов других блоков (условно повторять чужие стенды — нормально).

Страницы-прототипы подключают организмы **одной строкой** — подключателем `../Design-System/connect.js`
(так приходят шапка, боковое меню и правая панель); остальные организмы страницы подключают
вручную по путям `../Design-System/organisms/<имя>/…` (css + js — из readme блока) — и не пересобирают
их у себя.

Что добавлено «от себя» (размеры, цвета, состояния — которых нет в токенах/компонентах) —
живёт в общем журнале `Design-System/fixes.md`: раздел компонента, со статусами. В коде каждого места —
метка «пробел ДС №N» (номер ведёт к пункту журнала), в readme блока — строка-указатель.
Тексты в readme и журнале не дублируются.
