# page-footer — подвал страницы (и таблицы) — организм

Универсальная полоса внизу контента: разделитель + слот. Внутри слота — итоги
(блоками или ячейками по колонкам) и действия (кнопки); в «пустом» виде работает
как подвал страницы/диалога с одними кнопками. Источник — компонент новой ДС
**«Table footer»** (набор 59207:20759, вариант `Type=Default`, страница «🟡Table_DS»):
белая полоса с тенью 01 dp, разделитель сверху, слот («в блоке контента может быть
всё что угодно»). Наполнение — по примерам из макета:

- 59342:60193 — итоги блоками (блоки прижаты вправо);
- 59342:60191 — итоги ячейками + кнопки (Отмена / Сохранить / Сохранить и создать новый);
- 59366:46076 — итоги ячейками + кнопки (Сохранить / Провести);
- 14068:114035 и 11906:52165 («Номенклатура V2 Redesign») — подвал с кнопками страницы.

Собрано на компонентах новой ДС:

- **каркас** — «Table footer» (класс `ds-table-footer`): белая полоса, тень 01 dp,
  разделитель и контент с паддингами 32/12;
- **разделитель** — «Divider» (`ds-divider`): линия 1px, #E0E0E0;
- **действия** — «Button» (`ds-btn`): Size=M (36, r8, 14/500) — нейтральная контурная,
  акцентная, позитивная;
- **иконка-подсказка** — `info` из файла иконок Figma: 16 — в подписи ячейки (серая),
  24 — перед кнопками (красная #FF5252);
- **ячейки итогов и блоки** — своя разметка организма на токенах: готового класса
  в code-библиотеке нет (в Figma это компоненты семейства Table — `Type=Text`,
  `Type=Text sec/over`; когда выгрузка появится — заменить на классы компонента).

## Размеры (из компонента и примеров)

- полоса: ширина — по контейнеру (в примерах 1440 и 1184); разделитель 1px; контент —
  паддинги 32 (по бокам) / 12 (сверху-снизу), мин. высота 64;
- ячейка итогов: мин. высота 64, паддинг 12/16, между подписью и значением 4;
  подпись — 12/16 #616161, значение — 14/20 medium #333; «Итого:» — 14/20 medium;
- блоки итогов: гэп 32; блок 56 = подпись 12/16 + строка 14/20 + строка 14/20 medium
  (отрицательное значение — красное);
- действия: кнопки 36, гэп 8;
- в конфигурациях с ячейками вертикальные паддинги 12/12 не участвуют —
  полоса = ячейка 64 + разделитель (модификатор `.pf--cells`), как в примерах.

**Расхождения (как есть, не выравнивались):** «Провести» в примере #00C853, в токенах
ДС — #14B456 (в коде токен ДС); значения ячеек в примерах #212121 — в коде токен текста
#333; разделители и паддинги в примерах «Номенклатуры» #EEEEEE / 24 / 30 (старая ДС) —
в организме из нового набора (#E0E0E0 и 32/12), поэтому подвал с одними кнопками — 65
(а не 57); подписи кнопок в макете капсом (textCase=UPPER) — в коде регистр как на
остальных стендах ДС; в примерах 1-3 разделитель в слоях помечен выключенным, но на
рендере линия есть — в организме разделитель включён (как в наборе).

## Переключатели и модификаторы (как части компонента)

| Часть | Атрибут на корне |
|---|---|
| Контент — левая часть (итоги / блоки / текст) | `data-pf-content="off"` |
| Действия — правая часть (кнопки) | `data-pf-actions="off"` |

Нет атрибута — часть показана (дефолт). То же из js:
`PageFooter.set(блок, { content:false, actions:false })`. Без левой контентной части
кнопки остаются прижатыми вправо. Разделитель — всегда (как в компоненте Type=Default),
отдельного переключателя у него нет. Модификаторы вида: `.pf--end` — контент
прижат вправо (итоги блоками, подвал с кнопками); `.pf--center` — по центру (набор);
`.pf--cells` — ячеечная конфигурация (без вертикальных паддингов).

## Подключение

```html
<link rel="stylesheet" href="../Design-System/organisms/app-page-footer/page-footer.css?v=2">
<script src="../Design-System/organisms/app-page-footer/page-footer.js?v=2" defer></script>
```

Ассеты считаются от расположения скрипта — разметка работает с любой страницы
и при переносе папки (тот же приём, что у app-header, header-content и
table-header-actions). Страницы-прототипы подключают организм вручную по этим
путям (через `../Design-System/connect.js` он не приходит — блок нужен не каждой странице).

## Разметка (декларативно)

```html
<div class="ds-table-footer pf pf--cells">
  <div class="ds-table-footer__divider pf__divider"><div class="ds-divider"></div></div>
  <div class="ds-table-footer__content pf__content">
    <div class="pf__totals">
      <div class="pf__cell"><span class="pf__value">Итого:</span></div>
      <div class="pf__cell">
        <span class="pf__cell-head"><span class="pf__label">Цена продажи</span><img data-pf-icon="info" width="16" height="16" alt=""></span>
        <span class="pf__value">280,00 ₽</span>
      </div>
    </div>
    <div class="pf__actions">
      <button type="button" class="ds-btn ds-btn--m ds-btn--neutral ds-btn--outlined"><span class="ds-btn__label">Отмена</span></button>
      <button type="button" class="ds-btn ds-btn--m ds-btn--accent ds-btn--filled"><span class="ds-btn__label">Сохранить</span></button>
    </div>
  </div>
</div>
```

- Итоги блоками: вместо `.pf__totals` — `.pf__blocks` с блоками `.pf__block`
  (подпись `.pf__label` + строка `.pf__text` + значение `.pf__value`), полоса
  растягивается вправо модификатором `.pf--end`.
- Итоги по колонкам: `.pf__cell` (подпись `.pf__label` + значение `.pf__value`;
  иконка-подсказка в `.pf__cell-head`); у «Итого:» — одно значение.
- Действия: `.pf__actions` — кнопки ДС (`ds-btn`), основное действие — крайнее
  справа; иконка-подсказка — `<img data-pf-icon="info-negative" width="24" height="24">`.
- Ненужные части можно просто не размечать (или выключить атрибутом `data-pf-*="off"`).

## Правила

- Клики не заданы: кнопки — действия страницы, обработчики вешает она.
  Скрипт организма делает только две вещи: подставляет иконки (`img[data-pf-icon]` → SVG
  из этой папки) и переключает части (`PageFooter.set`).
- Иконки — точные SVG из Figma (`info`; 24-сетка: 16 — в подписи, 24 — подсказка;
  цвета зашиты: #616161 и #FF5252); глифы не заменять Material-шрифтом.
- Демо стенд — `demo.html`: живой блок с тумблерами частей (как части компонента) +
  конфигурации из примеров макета.
- Правки — только здесь.
