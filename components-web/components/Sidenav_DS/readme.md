# Sidenav — компоненты бокового меню

Семейство компонентов ДС для бокового меню приложения, как в Figma (страница «🟡Sidenav_DS»,
узел 55070-3437): **Element sidenav** (иконка свёртывания / аватар), **Sidenav header**
(L1 рейл 200 ↔ 52, L2 260), **Sidenav control** («Свернуть меню», 200/52 × Default/Hover/Press),
**Sidenav item** (L1/L2/L3 × Default/Hover/Active/Selected), **Sidenav footer** (L1 200/52, L2 версия).
Набор «Sidenav View» (55074-393) — это сборка меню целиком; на стенде он показан отдельной вкладкой как **шаблон-основа для организма**: рейл L1 200/52 и панель L2 260, высота примеров 1024. Живое поведение (шапка, шторка, JS) живёт в организме `DS/organisms/app-sidenav/`.

## Файлы в папке и кто их пишет

| Файл | Кто пишет | Что это |
|---|---|---|
| `element-sidenav.css`, `sidenav-control.css`, `sidenav-footer.css`, `sidenav-header.css`, `sidenav-item.css`, `sidenav-view.css` | генератор Фигма→CSS | вид компонентов (не правим, обновления перезаписывают); подключаются через `../index.css` |
| `demo.html` | **ручной** | демо-стенд с табами (компонент Tabs ДС): Element sidenav / Sidenav header / Sidenav control / Sidenav item / Sidenav footer / Sidenav View — порядок как в Фигме |
| `readme.md` | **ручной** | этот файл |

Витрины статичные: строки вариантов — как в наборах Figma. Состояния Hover/Press показаны
«замороженно» классами `st-hover`/`st-press` (в ДС это `:hover`/`:active`); selected/active —
классов в css нет (журнал №66) — `st-selected`/`st-active` на токенах ДС. Индикаторы состояний
и стрелки наведения — в css их нет (№58), на стенде собраны на токенах (числа из макетов);
точка-бейдж свёрнутого пункта — №57.

## Пробелы выгрузки и ручной слой

Неполное в сгенерированном слое закрыто ручным слоем `../../fixes.css` (п. 13) — те же приёмы,
что в организме `app-sidenav`; значения сверены с рендерами наборов Figma (по пикселям):

- №56 — строка L2: в css колонка и паддинги от L3 → ряд 40 с падом 16, гэп 8, подпись medium;
- №57 — свёрнутый L1: подпись/иконка без цвета (тёмное на тёмном) → белый токен; точка-бейдж → right 12/top 8;
- №58 — индикаторов и стрелок наведения нет в css → собраны в разметке стенда на токенах (белый 4×44 у L1 selected, синяя полоска 1,33×12 у L3 selected, стрелки hover);
- №59/88 — разделители: control → `#36474e` (токен), подвал → линия Divider 1×16 `#e0e0e0`;
- №63 — аватар Element sidenav: инициалы внутри круга (в css — колонкой под картинкой);
- №88 — иконки шапок: белый крестик L1 (`icon-inversive`), серые `icon-primary` у L2; ховер/пресс control красит `__content` (в css фон на корне перекрыт);
- №88 — слот иконки `.ds-element-sidenav__icon` в css не центрируется в квадрате 20×20 (липнет к углу; в Figma x2 y2) → центрирование в п. 13;
- №88 (View) — у root'а вариантов нет фона (`sidebar/l1|l2`), тени L2 и прижатия подвала вниз → п. 13; подвал L1 — снятие лишних паддингов/гэпа L2 и разделитель `contrast-3/900` (в выгрузке белый Divider; прежний `#e0e0e0` — ошибка выборки, поправлено и в вкладке Footer);
- №88 (View) — скролл: в наборе ползунок `neutral/700` 8×96 в полосе 12, у компонента Scroll в css — `neutral-300` и горизонтальная раскладка; Info-блок — 6× Text UI (min-height 52 против 48 в макете — пробел); шапка L2 в View — без стрелки «назад».

Открытыми в ДС остаются записи №56/57/59/63/88 (править в компонентах — ручной слой временный).

## Ассеты

Логотипы и аватар берутся из организма (единый источник): `logo-iiko-white.svg` (L1),
`logo-iiko-mark.svg` (знак свёрнутого рейла), `logo-iiko.svg` (подвал L2), `avatar-kk.svg`.
Иконки — точные **svg-пути из Figma** (как в ДС; селекторы `svg`/`svg path` уже есть в css компонентов):
шрифтовые глифы Material Icons из-за метрик уводили чернила от центра — шеврон collaps-icon
уезжал влево ~2,3px и не совпадал с рендером Figma, поэтому шрифт в стенде не используется.
