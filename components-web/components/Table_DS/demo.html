Таблица Обновлён 17 ноября 2026

Таблица — основной способ показать однотипные записи: гостей, товары, документы, остатки. В iiko таблицы нужны там, где данных много и их надо сравнивать по столбцам, искать и быстро менять: в списках гостей и товаров, документах, отчётах и настройках. Страница из двух частей: сначала анатомия — из каких компонентов собраны ячейка и строка и как они себя ведут, затем примеры — живые таблицы со сценариями: сортировка, фильтрация, управление столбцами, выбор и перетаскивание строк, иерархия, итоги и правка прямо в ячейке.

Анатомия таблицы

В Figma таблица собрана снизу вверх: сначала маленькие поля-«атомы», из них — обёртка поля, потом ячейка строки и сама строка. Ниже — вся цепочка: что во что вкладывается, какие у компонентов состояния и где они применяются. Компоненты лежат в секции Components файла Iiko Web DS (New).

Цепочка компонентов

  1. 1

    Input cell · Select cell · Chips input cell

    Атомы — самые маленькие редактируемые единицы. Input cell — обычный ввод текста. Select cell по нажатию открывает выпадающий список (Select Container), а выбранное значение применяется в ячейке. Chips input cell тоже открывает список, но введённый текст по Enter превращается в чипс.

    Состояния: Default, Hover, Focus, Focus + Placeholder, Focus + Value, Error, Error + Hover, Error + Focus, Disable. У Select cell нет Focus + Placeholder.

  2. 2

    Form field cell

    Обёртка поля: ставит атом в ячейку таблицы. Варианты повторяют атомы — Variant=Input, Variant=Select, Variant=Chips input. Держит паддинги и не даёт полю разъехаться внутри строки. Своих состояний нет — их задаёт вложенный атом.

  3. 3

    Table content cell

    Ячейка строки — один слот таблицы. Тип Type=Element — обычная нередактируемая ячейка: внутри Element cell (Text UI, Status, Button, Button icon, Icon size, Icon group, Input number, Checkbox, Slide toggle, Chips). Тип Type=Form field — редактируемая: внутри Form field cell с атомом.

    Состояния: Default, Null, Disable, Link, Hover, Focus, Edit, Error, Error + Focus.

  4. 4

    Table content row

    Горизонтальная строка таблицы со слотом Content: в слоте лежат Table content cell. Фон и зебра живут на строке, состояния полей — на ячейке, поэтому строка и ячейка наводятся независимо: строка подсвечивается целиком, действенная ячейка — своим фоном.

    Состояния: Default, Hover, Zebra, Disable, Table footer.

  5. 5

    Table header cell

    Ячейка шапки: подпись столбца и слоты под её действия — стрелка сортировки, воронка фильтра, шеврон раскрытия подколонок группы, шестерёнка настроек. Внутри та же цепочка, что и в теле, — Element cell → Text UI, поэтому подпись и иконки стоят в одной строке с отступом 8. Своей заливки и рамки у ячейки в сборке нет: фон и нижнюю границу держит полоса Table header row.

    Состояния: Default, Disable, Null. Ховера у ячейки нет: при наведении фон не меняется — реагирует только иконка действия (круглая подложка Icon size и цвет Icon/Primary).

  6. 6

    Table header row

    Полоса шапки — горизонтальный ряд Table header cell (в Figma полоса 486×36 из 6 ячеек по 81). На ней лежат заливка #F0F5FF, нижняя граница 1 px и скругления верхних углов 8, а ячейки внутри прозрачные — так фон и рамка не двоятся на швах. Ширины колонок задаёт таблица; шапка второго уровня собирается из двух таких полос подряд (Table 2 lvl).

    Состояния: Default. Живые реакции в шапке: клик по стрелке — сортировка столбца, по воронке — меню фильтра, по шеврону группы — раскрытие подколонок. Любая ячейка с действием (сортировка, фильтр, шеврон группы) действует всей площадью — курсор-рука, иконка → Icon/Primary, клик по площади повторяет действие иконки; активные состояния (синяя стрелка, синий шеврон) на ховере остаются синими. Фон ячейки при наведении не меняется.

Table header row
└─ Table header cell     подпись столбца + слоты сортировки и фильтра
   └─ Element cell → Text UI

Table content row
└─ Table content cell
   ├─ Element cell        нередактируемая: Text UI, Status, Button, Chips, Checkbox…
   └─ Form field cell     обёртка поля
      └─ Input cell / Select cell / Chips input cell

Правило простое: атом отвечает за ввод и свои состояния, Form field cell — за место в ячейке, Table content cell — за поведение ячейки в строке (наведение, фокус, правка, ошибка), а строка — за фон, зебру и выделение. Шапка устроена так же: заливку и границу несёт Table header row, действия столбца — Table header cell. Ниже — все ячейки и состояния, дальше на странице — живые примеры таблицы.

Table header row

Полоса шапки — горизонтальный ряд ячеек Table header cell. Заливку, нижнюю границу и скругление верхних углов несёт полоса, ячейки внутри прозрачные; в таблице это <tr class="ds-table-header-row"> с ячейками <th>. Ширины колонок задаёт таблица, шапка второго уровня — две такие полосы подряд.

Table header cell

Ячейка шапки описывает столбец: внутри подпись и слоты действий — стрелка сортировки, воронка фильтра. В Figma у компонента три состояния: Default — ячейка с подписью столбца, Disable — недоступный столбец (подпись серая), Null — пустая ячейка без подписи (под действия или служебный столбец). Отдельного состояния Hover у ячейки нет: на наведение отвечает только иконка действия — круглая подложка Icon size и цвет Icon/Primary, а фон ячейки остаётся прежним.

Виды ячеек

В ячейке может быть не только текст. В таблице два столбца: слева — название вида ячейки, справа — сама ячейка. Форматы: переключатель, статус, селект, текст с подписями, чипсы, текст, кнопка, чипс-поле, выключенная ячейка, ссылка, телефон, почта, адрес, только цифры, ошибка, пустая, иконка, чекбокс, группа иконок, кнопка-иконка, степпер и инпут. Наведение — фоном ячейки, ошибка — красным текстом, без рамок.

Table content cell

Это основной компонент, который мы используем в таблице для строк. Внутри — либо Element cell, либо Form field cell, поэтому ячейка отвечает только за поведение: наведение, фокус, правку и ошибку. Hover, Focus и Edit нужны действенным ячейкам, у нередактируемых (readonly) реакции нет. Обводка есть у Focus, Edit и Error + Focus; у Error — красный текст без рамки.

Table content row

Строка таблицы — ряд ячеек Table content cell одной записи; в таблице это <tr class="ds-table-content-row">. Состояния: Default, Hover (фон строки темнеет, ячейки наследуют), Zebra (чередование фона в длинных таблицах), Selected (выбранная запись), Disable (недоступная строка) и Footer — та же строка для итогов: линия переходит с нижнего края на верхний.

Input cell

Это редактируемая ячейка для таблицы. Используется как обычный инпут: слева и справа — иконки, между ними — значение. В покое у ячейки нет ни фона, ни обводки; наведение — только фон, синяя обводка появляется в фокусе, красная — в ошибке с фокусом.

Проверка значения — живые поля: телефон с маской, почта, только цифры и адрес. Ошибка в покое — красный текст и красная иконка с подсказкой, при клике появляется красная рамка.

Select cell

Это редактируемая ячейка для таблицы. По нажатию выпадает Select (Container) и можно выбрать элементы из выпадашки — они применяются в ячейке. Обводки и фоны состояний — те же, что у Input cell.

Chips input cell

Это редактируемая ячейка для таблицы. По нажатию выпадает Select (Container). Также можно ввести текст и нажать Enter — значение обернётся как Chips. Состояния те же, что у Input cell: фон на ховере, обводка — только у Focus и Error + Focus.

В мобильном таблица превращается в карточки

На узком экране строки перестраиваются в карточки: название записи становится заголовком, остальные значения — парами «подпись — значение», а чекбокс выбора уходит в правый верхний угол. Так таблица читается на телефоне без горизонтальной прокрутки и без мелкого шрифта.

Примеры таблицы

Дальше — рабочие таблицы по сценариям: сортировка, фильтрация, управление столбцами, выбор и перетаскивание строк, иерархия, итоги и правка прямо в ячейке. Каждый сценарий — одна живая таблица: заголовок говорит, что она умеет, подпись — что можно сделать.

Сортировка по клику на стрелку или на ячейку шапки

Клик по стрелке — или по любому месту ячейки шапки, где она есть, — сортирует столбец по возрастанию, повторный клик — по убыванию, третий — снимает сортировку. Серая стрелка — «столбец можно сортировать», синяя — текущее направление и активный столбец. У самой ячейки фон при наведении не меняется: курсор становится рукой, а стрелка — Icon/Primary; круглая подложка появляется при наведении на иконку.

Сортировка «на лету» — по значениям в ячейках, без перезагрузки. Числовые столбцы сравниваются как числа, текстовые — без учёта регистра.

Фильтрация по значениям столбца

Ячейка заголовка с воронкой открывает меню столбца — и по клику на иконку, и по клику на любое место ячейки: в шапке — «Выбрать все», ниже — значения с цветными точками и чекбоксами, внизу — «Сбросить» и «Применить». Пока фильтр включён, на иконке горит синяя точка, а «Сбросить» возвращает все значения. На наведении ячейка показывает курсор-руку и затемняет иконку до Icon/Primary; фон ячейки не меняется.

В макетах у фильтра есть расширенный вариант — условия по столбцу («столбец · условие · значение»). Здесь показан базовый сценарий «отметить значения»; расширенный фильтр — отдельная задача.

Фильтрация + сортировка одной иконкой

В заголовке одна иконка: она открывает меню столбца. На первом уровне — только команды: сортировка, быстрые условия («за последние 3 дня», «Удаленные»), входы в фильтры «Сегменты» и «Пол» и пункт «Скрыть столбец». Пункты фильтров открывают меню второго уровня со списком значений, «Выбрать все», футером и кнопкой «Применить» (она в дизейбле, пока ничего не изменили). «Применить» применяет фильтр и закрывает второе меню — меню столбца остаётся на месте, можно сразу настроить что-то ещё. Сортировка тоже применяется сразу, не закрывая меню: выбранное направление отмечается галочкой. На иконке фильтра в шапке и у пункта в меню появляется синий бейдж, сама иконка остаётся серой.

Скрытие и порядок столбцов

Шестерёнка стоит в последнем столбце шапки и закреплена справа — меню настроек всегда под рукой. В меню видно, какие столбцы показывать и в каком порядке. Обязательного столбца в списке нет вовсе: его не скрыть и не переставить. Изменения применяются по кнопке.

Порядок столбцов можно менять и перетаскиванием в самой шапке — см. раздел «Перетаскивание колонок». В настройках порядок задаётся перетаскиванием за ручку из шести точек.

Двухуровневый заголовок

Столбцы объединены в группы: первая группа — «Товар», внутри неё «Название» и «Артикул»; дальше «Остатки на начало», «Приход», «Продажи», внутри — «Кол-во» и «Сумма». Сортировать можно по любой подколонке, в итоговой строке считаются суммы по каждой группе.

Одинаковые подписи внутри групп («Кол-во», «Сумма») не дублируются в каждой группе — читаются вместе с названием группы. В мобильном виде такая шапка не помещается: её заменяет карточка строки.

Раскрытие подколонок вправо

У группы «Приход» есть свёрнутое состояние: одна колонка «Всего». Нажмите на ячейку группы с названием (или на стрелку, или потяните разделитель вправо) — раскроются подколонки: от поставщика, отквитировано, возврат от покупателя, инвентаризация. Повторное нажатие сворачивает группу обратно. Ячейка группы со стрелкой действует всей площадью: на наведении — курсор-рука и стрелка Icon/Primary, фон не меняется.

Разделители и изменение ширины

Три режима разделителей: без линий, на весь столбец и короткие — только в шапке. Ширину меняют за границу между столбцами: при наведении на неё появляется одна синяя линия на всю высоту таблицы — ровно там, где стоит текущий разделитель (в режиме «на весь столбец» серая линия становится синей). Убрали курсор — линия исчезла. Тянется только свой столбец, соседние остаются на месте; если таблица перестала помещаться, она прокручивается внутри своего контейнера.

Разделители «на весь столбец» помогают читать широкие таблицы с группами, «короткие» — не дробят простые таблицы. По умолчанию предлагаются короткие линии.

Закрепление первого и последнего столбцов

Таблица шире и выше своего контейнера. Первый столбец («Товар»), последний («Итого») и футер с итогами закреплены: они остаются на месте при прокрутке вбок и вниз, так что название, итог и сумма видны одновременно. На границах закрепления появляется разделитель.

Закреплено со всех сторон: первый столбец держит название записи, последний — итог строки, футер снизу — общий итог. Прокрутите таблицу вбок и вниз. Над футером при прокрутке линия 2 px, в самом низу она становится 1 px — как у закреплённых столбцов.

Наведение, выбор и открытие строки

Наведение подсвечивает строку. Чекбокс выбирает строки; подсветка выбранной строки — вариант оформления, сравните две таблицы ниже. Панель с данными записи открывается только по клику на имя записи (синяя ссылка), а не по всей строке: иначе нельзя спокойно выделять текст и нажимать иконки. Одна строка выключена: её содержимое недоступно и не реагирует.

Вариант 1 — без подсветки. Отметили чекбокс — фон строки не меняется: выделение видно только по чекбоксу, а подсветка остаётся только при наведении.

Вариант 2 — с подсветкой. Выбранная строка остаётся подсвеченной, когда курсор ушёл.

Перетаскивание колонок

Ручки по умолчанию нет: при наведении на столбец над его шапкой появляется иконка из шести точек — по центру верхней границы таблицы, половина иконки выше шапки, половина на ней. За неё и тянем колонку: она «летит» за курсором призраком, а синяя линия на всю высоту столбца покажет место вставки. У столбца «Имя» ручки нет: он закреплён по смыслу, перетаскивать его нельзя.

Порядок колонок меняется только в интерфейсе: если он сохраняется в настройках пользователя — это отдельное требование. Неперетаскиваемый столбец не должен выглядеть «сломанным»: отсутствие ручки — достаточный признак.

Перетаскивание строк

Строку можно перетащить за ручку: она превращается в призрак и летит за курсором, а синяя линия показывает, куда строка встанет. Исходная строка не подсвечивается серым — важно не «схватил ли я строку», а «куда она встанет».

Тот же сценарий в таблице с чекбоксами: ручки в строке нет, пока на неё не навели. При наведении появляется иконка из шести точек на левой границе таблицы, по центру по высоте строки — левая половина иконки выступает за таблицу; тянем строку за неё.

Массовые действия над строками

Чекбокс в шапке выбирает все строки. Как только что-то выбрано, над таблицей появляется панель: сколько строк выбрано, какое действие выполнить и кнопка «Применить»; рядом — «Снять выбор».

Действия в списке — заглушки: реальных операций в примере нет. Если выбрана одна строка, панель массовых действий не нужна — работают действия в строке.

Действия в строке

Кнопки появляются при наведении на строку: редактировать, копировать, удалить. Действия выполняются сразу — строка меняется на месте, без перехода на другой экран.


Вариант с меню. В конце строки — Icon Size с тремя точками: по нажатию открывается Menu с действиями над строкой. Иконка видна всегда, меню не перекрывает данные.

Скрытые до наведения кнопки нельзя делать единственным способом действия: на тач-устройствах наведения нет — там действия должны быть видны постоянно или жить в меню строки.

Добавление новой строки

Флоу добавления зависит от бизнес-задачи, поэтому показываем разные варианты.
Вариант 1 — кнопка «Добавить строку»: она создаёт строку с полями ввода — заполнять можно сразу в таблице, не открывая отдельную форму. Enter и клик мимо фиксируют значения, пустая строка убирается.


Вариант 2 — автоматическое добавление. Кнопки нет: заполните «Наименование» и нажмите Enter или просто уберите фокус из ячейки — под строкой сразу появится новая пустая.

Копирование строки

Кнопка копирования в строке создаёт дубль под оригиналом. Копия сразу доступна для правки — например, чтобы поменять одно поле и сохранить.

Зебра, рамки и выравнивание

Один и тот же набор данных можно показать по-разному: обычные строки, зебра или рамки между ячейками. Выравнивание числового столбца переключается — по левому краю, по центру или по правому. Выбирайте варианты в панели над таблицей.

Зебра помогает в длинных таблицах без линий; рамки — когда важно сопоставлять значения в столбце. Числа в ДС по умолчанию выравниваются по правому краю — так разряды совпадают.

Иерархия строк

Строки вкладываются друг в друга с шагом 28 px: у папок есть стрелка, вложенность видна по отступу. Раскрытая папка показывает раскрытую иконку. Стрелка у папки раскрывает и сворачивает всю ветку; вложенные строки не сортируются отдельно от родителей.

Глубокую иерархию (5+ уровней) в макетах не показывали: шаг 28 px на узком экране съедает ширину — на мобильном такие таблицы стоит разворачивать в карточки.

Строка-группа на всю ширину

Строка-папка не подчиняется колонкам: в ней свой контент на всю ширину таблицы — название группы, счётчик и действия. Раскрывается стрелкой, внутри — обычные строки.

Такая строка нужна там, где группа важнее столбцов (акции, категории, разделы документа). Внутри строки-папки не должно быть данных, которые нужно сравнивать по столбцам.

Итоги, пагинация и закреплённый футер

Итоговая строка закреплена внизу: при прокрутке таблицы суммы остаются видны. Ниже — пагинация: размер страницы и переход по страницам, а над таблицей — сколько записей показано.

Редактируемые ячейки

Таблица из двух-трёх колонок заменяет форму: значения правятся прямо в ячейках, селект открывает список. Ячейка — это компонент Table content cell (Type=Form field) с атомом Input cell или Select cell: в покое — серая граница ячейки, на ховере — только фон, в фокусе — синяя обводка вместо серой, ошибка — красный текст и иконка с подсказкой без рамки, красная рамка — в паре с фокусом. Часть ячеек только для чтения — например, «Код подключения» генерируется системой.

Открытый вопрос: в макетах не описано, когда сохраняются значения — сразу по уходу из ячейки или по кнопке «Сохранить» под таблицей. Здесь сохранение мгновенное (по Enter / клику мимо), а «Сохранить» в макете — часть формы, а не таблицы.

Скрытие и раскрытие позиций

Стрелка в строке раскрывает под ней служебные строки: подпись «Названия ЕГАИС» и по строке на каждое название с его кодом — у одного товара названий может быть несколько. Название — синяя ссылка: клик открывает карточку позиции в боковой панели справа. Двойная стрелка в первой ячейке шапки сворачивает все строки сразу, после этого она смотрит в обратную сторону и разворачивает всё обратно. Сортировать можно по любому столбцу.

Раскрытая строка не должна ломать сетку: дополнительный блок идёт на всю ширину таблицы. Если данных много, лучше открывать боковую панель, а не растягивать строку.
