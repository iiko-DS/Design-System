# Как собирать демо-стенды компонентов

Инструкция для сборки демо-стендов `components-web/components/<Имя>_DS/demo.html`.
Собрана из того, что уже зафиксировано: комментарии самих стендов (шапки + «Пометки для ревью»),
`readme.md` папки, гайд «Как собирать из дизайн-системы» (репозиторий прототипов), конвенция вкладок
(коммиты `74da143` «Basic example + вкладки по наборам» и `19863b5` «вкладки по вариантам Фигмы»)
и журнал `Design-System/fixes.md`. Ничего не выдумывать — при неясности смотреть эти источники.

## 1. Что такое демо-стенд

- У каждого компонента (семейства) — **свой** `demo.html` в его папке `components-web/components/<Имя>_DS/`.
  Файл ручной — генератор его не трогает (эталон из readme: `Datepicker_DS/demo.html`).
- Стенд показывает компонент **как в Фигме**: витрины вариантов + примеры с канвы.
  Принцип «всё как в фигме»: чего нет в данных — не выдумываем (обвязка с пометкой
  или «не воспроизводим» с причиной).
- ⭐ **Смысл работы — поиск недочётов** (слова владельца, 13.10.2026): не просто выложить витрины,
  а найти, чем Figma расходится с ДС (css, токены) и собранной вёрсткой; каждая находка —
  «подсказка ДС» (§6), из подсказок живёт журнал. Сборка без поиска находок работой не считается.
- Сборка — **только компоненты ДС** (классы `ds-*`) и **токены** (`var(--ds-*)`).
  Макет задаёт структуру и тексты; внешний вид задаёт ДС. Обвязка стенда = только раскладка:
  позиционирование, ширины, гэпы контекста.
- Внутреннюю геометрию компонента не подгонять (ширины/высоты/паддинги извне):
  «не влезает» — вопрос к раскладке или к ДС.
- Стенды самодостаточные и правятся независимо; условно повторять чужие — нормально.

## 2. Источники — смотреть сразу все

- **Figma** (read-only): канва «<Имя>_DS» — номер страницы/канвы и номера узлов.
  Состав — по дереву слоёв: внутри вариантов часто **инстансы других компонентов**
  (Input внутри Select form и Input number, Button/Button icon в сегментах toggle, Sidenav item
  в примерах и т.п.). Числа — из свойств узлов; **тексты — дословно** (орфография канвы сохраняется).
- ⚖️ **ЗАКОН (слои и правая панель; слова владельца, 07.10.2026: «Это закон»).** Фигма читается
  **только по слоям**: дерево слоёв + настройки в **правой панели** — для КАЖДОГО компонента,
  каждый компонент разбирать **дословно** (состав по узлам, размеры, состояния, значения).
  **В компонентах почти всегда вложены инстансы ДРУГИХ компонентов** («очень много зависимостей»):
  иконка слева и крестик баннера — инстансы «Icon size» (Size=20), а не «просто иконка»;
  Input внутри Select form / Input number / Datepicker; Button и Button icon в сегментах Button toggle;
  Button group в подвале Dialog и в баннерах; Badge в пунктах Sidenav и т.д.
  Вложенный инстанс в сборке воспроизводится **именно компонентом ДС** (контейнер `ds-icon-size`,
  `ds-btn-group` и т.п.) со всеми зависимостями — один источник стилей: правка компонента/токена
  доезжает до любого места использования. Перед сборкой — выписать состав по слоям (что вложено
  в что, с какими настройками правой панели).
  ⭐ Повторено жёстко 19.10.2026 (заказчик: «Ещё раз для всех демо страниц компонентов обязательно
  смотреть слои и настройки в фигме… Это уже прописано кажется также везде!»): правило действует для
  ВСЕХ демо-страниц и ВСЕХ вкладок — в том числе при повторных проходах и точечных правках, не только
  при первой сборке. Нельзя «помнить» структуру — каждый раз открыть слои и правую панель. Свежий
  пример (Dialog): `Icon size [Size=24, Content=Icon]` → скрытый `State [State=Hover] 32×32` →
  `close` 24×24 → глиф `icon` 14×14; живому триггеру — `ds-icon-size--state` (журнал №203, №204).
- ⭐⭐ **ОБЯЗАТЕЛЬНАЯ ПРОЦЕДУРА ПРОВЕРКИ ВЛОЖЕННЫХ ИНСТАНСОВ (повторено владельцем 07.10.2026,
  «это максимально важно… придерживайся всегда, всегда!»).** Перед сборкой/правкой КАЖДОГО стенда:
  1. Пройти дерево слоёв **каждого варианта и каждого примера** и выписать для **каждого слота**,
     что в нём лежит: какой инстанс какого компонента (с Size/State из правой панели).
  2. В разметке все вложения воспроизвести классами этих компонентов ДС.
  3. Чек перед сдачей: **в слотах нет ни одного голого глифа `material-icons` и ни одного
     самодельного `<svg>`** — иконки ВСЕГДА через контейнер `ds-icon-size` (размер по месту:
     --4x/16, --5x/20, --6x/24, --8x/32…; иконкам-триггерам — модификатор `--state`;
     fixes.css п.14, пробел выгрузки №89, правило №99).
  Типовые вложения, которые легко пропустить: **Icon size** (все иконки слотов — полей, пунктов,
  кнопок, статусов), **Checkbox / Radio button / Slide toggle** (пункты Select, Element select,
  списки), **Button group** (подвалы Dialog/Banners, контейнер Select), **Scroll** (контейнер Select,
  меню, списки), **Title / Divider** (контейнеры), **Input** (Select form, Input number, Datepicker),
  **Button / Button icon** (сегменты, тулбары), **Badge / Counter** (пункты Sidenav, Element select).
- **css компонента** (`components/<Имя>_DS/*.css`) и **tokens.css** — что есть классами и токенами.
- **fixes.css** — что уже обойдено (номера пунктов), чтобы не чинить заново.
- **iiko-ds-spec.md** — какие бывают варианты и как называются классы (прочитать до сборки).
- Сверка — с рендером Figma (скрин) и значениями css/токенов.

## 3. Каркас страницы (единый у всех)

Подключение в `<head>` (порядок):

```
font.css → tokens.css → styles.css → ../index.css → ../../fixes.css
```

(`fixes.css` — последним.) Дополнительно по потребности: Material Icons
(линки `…icon?family=Material+Icons` + `…Material+Icons+Outlined` и правило
`.material-icons { font-family: 'Material Icons Outlined'; }`), js компонента
(пример: `Datepicker_DS/datepicker.js`).

**Шапка-комментарий** `<!-- … -->` — обязательные поля:

- компонент, страница/канва Figma + номер;
- компоненты: имя (номер, число вариантов, состав и ключевые числа по узлам);
- примеры/сборка: имя/номер, что внутри, тексты;
- пробелы и обойденное (пункты fixes), «решить в ДС»;
- `Журнал DS/fixes.md №N`.

**Разметка:**

- `.demo-bar`: заголовок «<Имя> — демо стенд» + справочная строка
  «Figma: … (id) — N вариантов · примеры: …»; для живых примеров — счётчик `.demo-bar__state`.
  Слово «набор» не использовать: в Figma его нет (проверено по выгрузкам `ds-components.json` и `ds-full.json`) —
  формулировки владельца, 07.10.2026.
- `.view` → вкладки → панели.
- **Вкладки** — компонент ДС Tabs:

```html
<div class="ds-tabs" role="tablist" aria-label="<Имя>">
  <button class="ds-tab ds-tab--active" role="tab" aria-selected="true" data-vtab="basic">Basic example</button>
  <button class="ds-tab" role="tab" aria-selected="false" data-vtab="<компонент>"><Имя></button>
</div>
<div class="panel" data-vpanel="<компонент>" role="tabpanel" hidden>…</div>
<div class="panel" data-vpanel="basic" role="tabpanel">…</div>
```

Переключение — общий скрипт внизу страницы (копировать как есть):

```js
var tabs = Array.prototype.slice.call(document.querySelectorAll('.ds-tab[data-vtab]'));
var panels = Array.prototype.slice.call(document.querySelectorAll('[data-vpanel]'));
tabs.forEach(function (btn) {
  btn.addEventListener('click', function () {
    tabs.forEach(function (b) {
      var on = b === btn;
      b.classList.toggle('ds-tab--active', on);
      b.setAttribute('aria-selected', on ? 'true' : 'false');
    });
    panels.forEach(function (p) { p.hidden = p.getAttribute('data-vpanel') !== btn.getAttribute('data-vtab'); });
  });
});
```

- **Состав и порядок вкладок**: первой — **«Basic example»** (если на канве есть примеры/сборка),
  далее — **по вкладке на каждый компонент Figma, имя таба = имя компонента**, порядок — как в Фигме.
  Нет блока примеров — первая вкладка = первый компонент.
- Внизу файла — спрайт иконок `<svg><symbol>…`; `fill: currentColor` задавать **на самом svg**
  (правило на `svg path` не пробивает shadow-DOM `<use>` — иконки рендерятся чёрными).
- Классы обвязки стенда — `snap-*` (капсулы, подписи, сноски); компоненты ими не переписываются.

## 4. Содержание панелей

- **Панель компонента** — витрина как в Figma: варианты рядами, как в Figma; числа и тексты — как в Figma.
  **Свойства Figma (панель Properties) подписями НЕ выводить** — никаких ярлыков вида «Style=…»,
  «Type=…», «State=…», «Variant=…», «Size=…» на странице (правило владельца, повторено 07.10.2026);
  свойства используем только для того, какие примеры собрать.
  **Запрещены и составные подписи-комбинации** («M · Default», «Lvl 2 · On», «Focus · value»,
  «Error · hover», «Position=First»): у кадров витрин подписей свойств нет вовсе (замечание владельца
  08.10.2026: «Убирай все эти подписи… во всех компонентах»). Допустимы: заголовок витрины
  «<Компонент> — N вариантов», пояснительные подписи (Basic example, Заметки канвы, Пометки для ревью).
- **Витрины состояний — статика**: живые реакции мыши (ховер/фокус) внутри витрин выключаются обвязкой
  стенда (`pointer-events: none` на элементах витрин; у Table — все вкладки кроме «Basic example»);
  состояния показываются замороженными образцами (`st-*`), живая механика — только в «Basic example»
  (владелец, 13.10.2026: «в этой вкладке не может быть ховеров… это статика и показаны состояния»).
  ✅ Где состояние вызывается действием — в «Basic example» делаем его вызываемым (владелец, 13.10.2026:
  «эти состояния и живые примеры нужно вывести в бейсик эксемпл — не только ховер, а и фокус, эдит»):
  у Table — клик по ячейке даёт фокус, двойной клик — редактирование (contenteditable, Enter — закончить),
  в живых строках — ячейки в состояниях (ошибка/ссылка/выключено/пусто).
  ✅ **Ячейки в таблицах — два вида** (решение владельца, 14.10.2026): **обычные** (`ds-table-content-cell` —
  текст/элементы через слот `__element`) и **ячейки-поля** (**Element Form Field**: сам компонент является
  ячейкой — вставляется вместо ячейки контента, не через слот; сейчас это инпут, селект и чипс-инпут).
  Компоненты в ячейках-полях ведут себя **по механике как их обычные компоненты**, подстроенные под ячейку:
  инпут — фокус/каретка/ввод; селект — клик открывает выпадающее меню, выбор подставляется в значение;
  чипс-инпут — Enter добавляет чип, «✕» чипа удаляет, «✕» поля очищает ввод. Эталон обвязки —
  `Table_DS/demo.html`, «Basic example» (ячейки Element Form Field на строках под таблицей).
  ⭐ **Таблица — эталон сборки** (утверждено владельцем 16.10.2026 — «Не только ховер, а вообще всё…
  так будут собираться все прототипы и таблицы… как инструкция»; эталон — пример «All example»,
  журнал №195): так собирается любая таблица. Полоса над таблицей — организм `app-table-header-actions`
  одной ширины с таблицей (отступ 8; слева заголовок/настройки, справа только кнопки-иконки; при выборе —
  массовые действия). Шапка: чекбокс «выбрать все» (36) + сортируемые колонки (стрелка в Element right,
  активная #448AFF / остальные #616161, клик — сортировка), фильтр — меню на компоненте Menu
  («Сбросить/Применить», точка Badge), настройки колонок — шестерёнка + меню (drag за иконку, синяя линия
  вставки, обязательные в Disable), разделители 1×20 #E0E0E0 на стыках, активные — ресайз колонки слева
  (наведение — линия на всю высоту, захват — синяя). Строки: чекбокс выбора + выбранная строка Accent/5
  #F8F9FC (наведение не перекрашивает), зебра — опция `--zebra`; наведение — подсветка по СТРОКЕ единым
  тоном Table/Hover #F5F5F5 (уточнение владельца 16.10, вечер: «смотри на ховер по строчке»; отдельная
  подсветка ячейки не используется, рамок нет); клик — фокус (синяя inset-рамка); состояния Focus/Edit —
  демонстрация на стенде (двойной клик — правка: ввод, Enter/blur — закончить, Esc — вернуть; в продукте —
  только где предусмотрена задачей); клик по ссылке/контролу рамку не даёт; нередактируемые —
  `--readonly` (ни наведения, ни фокуса, ни правки); компоненты в ячейках — через слой `__element`, ячейки-поля —
  сам компонент вместо ячейки (инпут/селект/чипс-инпут с масками и ошибкой текстом); длинные значения —
  2 строки + «… ещё»; ≤1024 адаптив в карточки (пары «подпись → значение», ховеров нет). Глобальные
  правила механик — fixes.css п. 42 (работают на всех страницах с подключением ДС); полный перечень —
  гайд `Prototype-Guide/prototyping-guide/дизайн-система/сборка-из-ДС.md`, раздел «Таблицы — эталон сборки».
- ⭐ **Колонка действий строки — фиксация только на наведении** (правило владельца, 19.10.2026:
  «фикс только при наведении, а не всегда»): действия строки скрыты до наведения; при наведении/фокусе
  строки её колонка действий прижимается к правому краю видимой области (`position: sticky; right: 0`)
  с фоном строки (#F5F5F5; выбранная — Accent/5 #F8F9FC), чтобы текст не просвечивал под иконками.
  В покое колонка обычная — без фона, тени и разделителя («белого столба» нет); постоянный sticky/тень/
  линию не задавать. ⚠️ Правило `.ds-table-content-cell:hover…{background:transparent}` снимает фон
  у самой ячейки при наведении — для колонки действий нужно исключение `:not(.t-c-actions)`, иначе текст
  просвечивает сквозь иконки. Эталон — прототипы «Киоски · Баннеры» v1/v2 (журнал №206).
- ⭐ **Ширины колонок — по самому длинному в колонке — ДЕФОЛТ для всех таблиц** (правило владельца, 19.10.2026:
  «лишний отступ справа не нужен — самое длинное по всему столбцу будет шапка», «По всем таблицам так…
  это условно дефолтное правило»): колонка получает фиксированную ширину
  = max(шапка: текст + 8 + иконка сортировки 20; контент: значение + паддинги 16), без `flex-grow` —
  лишнего запаса справа нет; растягивается только одна колонка (в списке групп — «Название», в баннерах —
  «Место расположения»/«Наименование»). Применено: список групп (74/129/139/103/76), таблица баннеров
  группы (51/31/250/230/85/68), списки баннеров v1/v2 (36/188·216/52/184/243/146/201/76). Журнал №207, №208.
- ⭐ **Ссылки — единый паттерн** (правило владельца, 19.10.2026: «Если это ссылка — она сразу синяя…
  Ещё раз всё везде одинаковое»): кликабельные названия и «ещё» — #448AFF сразу (Text/UI Link),
  на ховере только подчёркивание; удалённые — #9E9E9E + line-through. Журнал №209.
- ⭐ **Булево состояние в колонке — галочка, не статус** (правило владельца, 19.10.2026): два состояния
  (активен/неактивен) — иконка `check` (Icon/Positive #14B456, `ds-icon-size--5x`) при включённом,
  тире «—» при выключенном; статус-бейдж не выводим; сортировка — по признаку. Журнал №210, №212.
- ⭐ **Нет данных в ячейке — тире «—»** (правило владельца, 19.10.2026: «Везде по всем таблицам,
  если нет данных в ячейке, ставим дефис, тире»): пустых текстовых ячеек быть не должно — выводим «—»;
  не трогаем чекбокс/фото/иконки/действия и булеву колонку (галочка/пусто). В прототипах — fallback'и
  в рендере + `fillEmptyCells()` после рендера. Журнал №211.- ⭐ **+4px «воздуха» с одной стороны по прижатию и выравнивание** (правила владельца, 19.10.2026):
  (а) если в таблице есть свободное место — учитываем текст/число и прижатие: текст — +4 справа,
  числа и даты — +4 слева, иконки по центру — по +4 с двух, действия — +4 слева; чекбокс 36;
  нет места (переполнение) — не добавляем; (б) текст — слева, числа и даты — справа (и шапка,
  и ячейка), иконки — по центру, артикулы/SKU/коды — слева. Журнал №213–216.- ⭐ **Выпадашки с кнопками действий — применение по кнопкам** (правило владельца, 14.10.2026: «везде, где
  в выпадающем меню или селекте есть кнопки действий, применение изменений происходит только после клика
  на эти кнопки; если кнопок нет — сразу»): меню с футером (фильтр колонки, «Настройки колонок») — галочки
  это черновик: открытие показывает применённое состояние, закрытие без «Применить» отбрасывает правки,
  «Применить» — принять (фильтр: точка на иконке; колонки: скрыть/показать и новый порядок перетаскиванием
  строки за иконку перемещения), «Сбросить» — применить сразу (и вернуть дефолтный порядок)
  (эталон — `Table_DS/demo.html`); выпадашки без кнопок (селекты выбора) — выбор применяется сразу.
- **Basic example** — **агрегатор стилей, типов и состояний**: показывает общую картину компонента
  и его работу (определение заказчика, 07.10.2026).
  - **Динамический компонент** (автокомплит, селект, тогл…) — **только живой пример**: «просто как
    работает реально» (ввод, клики, открытие/закрытие — всё живое; поведение — обвязка стенда);
    статичные кадры примеров со страницы не воспроизводим (правило заказчика, 07.10.2026).
    Повторено 09.10.2026: «в басик эксепл просто работающий компонент — один, два варианта».
  - **Всё, что в примере есть, — работает** (правило заказчика, 19.10.2026: «Мы делаем этот эксемпл
    для того чтобы он работал! И все что в этом компоненте организме находится должно работать…
    Нужно понять как открывается диалоговое окно и как оно закрывается и если есть скролл, то он
    должен также работать»): модальное окно/панель открывается и закрывается реально —
    крестик, Esc, кнопка действия, клик по затемнению (Backdrop из ДС); если в компоненте есть
    скролл — контент действительно прокручивается (колесо/тач), а ползунок компонента Scroll
    перетаскивается и синхронизирован со scrollTop; все контролы (поля, тумблеры, чекбоксы,
    селекты) — живые. Витрины остальных вкладок при этом остаются статикой (правило 13.10).
    Эталон — `Dialog_DS/demo.html`, «Basic example» (журнал №202).
  - **Не динамический компонент** (бейдж, текст, статус…) — можно показывать примеры со страницы
    (тексты дословно, как в Figma).
  - **Отдельной вкладки «Примеры» нет ни у одного компонента** (правило владельца, 09.10.2026:
    «Никакого таба примеры не должно быть»): примеры со страницы живут внутри «Basic example»
    (не динамический компонент) либо не воспроизводим вовсе (динамический).
  - статичные состояния — «замороженные» стенд-классы `st-hover/st-press/st-focus` —
    **значения теми же токенами**, что `:hover/:active` в ДС; где есть реальные классы ДС
    (`--error`, `--disabled`…) — использовать их;
  - витрины и примеры — **без подписей-описаний** («Button + Counter (Positive)», «Icon size 24 (date_range) + …»
    и т.п. — лишнее; замечание заказчика 07.10.2026).
- **Хвост каждой панели** — `snap-note` «**Пометки для ревью**: (а)… (б)…»:
  состав по узлам, что «не воспроизводим» и почему.
- **Находки-недочёты выводятся ОДИНАКОВО у всех — механизмом «Подсказок ДС»** (§6):
  кнопка «**Подсказки ДС · N**» + номерные метки у мест (клик — всплывашка «№N. суть»);
  формат подсказки: номер пункта журнала — место — что не сходится → что доделано.
  «Пометки» — справка по сборке; подсказки и отчёт — одно и то же (владелец, 13.10.2026).

## 5. Железные правила

- **⭐⭐ Реальные компоненты и паттерны поведения — как в Material Design / Angular Material** (заказчик,
  19.10.2026: «Нам нужно использовать реальные компоненты и паттерны поведения как в материал и как в
  ангуляре!»): каждый контрол/сценарий — по реальному паттерну (M3: Select, Chips, Combobox, Menu, Dialog;
  Angular Material: `mat-select multiple`, `mat-autocomplete`, `mat-chip-grid`, `MatDialog`): состав,
  состояния, клавиатура, закрытие — как у настоящего компонента. Свои виджеты не изобретаем и паттерны
  не смешиваем; нет единого компонента в ДС — композиция из компонентов ДС по тому же паттерну (пример:
  мультиселект с чипами = Chips Input + Select container + Checkbox в `element-left` у каждого пункта;
  «Выбрать все» — отдельный пункт с Checkbox и indeterminate).
- Тексты — дословно. Число бейджа — реальное из данных (при больших значениях — «99+»).
- **Слово «набор» не используем** — в Figma его нет; говорим «компонент», «витрина вариантов»,
  «Figma: Имя (id) — N вариантов» (правило владельца, 07.10.2026).
- Иконки — **только Outlined**; Material Icons — по имени шрифтом; нет глифа в шрифте —
  точный svg-путь из Figma.
- ⭐ **Каждая иконка и каждый слот — проверены на вложенный инстанс** (процедура и чек-лист — ЗАКОН,
  раздел 2). Голые глифы и самодельные `<svg>` в слотах запрещены; иконки — только через `ds-icon-size`
  (размер по месту; триггерам — `--state`); прочие вложения — компонентами ДС (`ds-checkbox`,
  `ds-radio`, `ds-slide-toggle`, `ds-btn-group`, `ds-scroll`…). Повторено владельцем 07.10.2026.
- Фон витрин — как фон в Figma (например `#F8F9FC`, если белое на белом не читается).
- ⚠️ **Точные размеры/поля/отступы САМОГО ФРЕЙМА-контейнера канвы НЕ воспроизводим** (замечание заказчика
  09.10.2026: «я не просил делать прям как у фигмы сделаны размеры фрейма и прочего… компоненты мне нужны как
  в фигме со всеми слоями как там и настройками — это самое главное»): воспроизводим **компоненты** (их вид,
  слои, настройки: вариант/размер/состояние/слоты) и **их расположение** (порядок, колонки, ряды);
  поля/ширины обвязки — обычные стендовые.
- Хардкод цветов/размеров — только при отсутствии токена: пометка в коде + пункт в журнал.
- **Не воспроизводим**: служебные шапки «Header components» и служебные пометки на странице
  («слетели хедеры» и т.п.); для динамических компонентов — статичные кадры примеров (там только
  живой пример, см. раздел 4); мобильные версии (`_mob`) и сравнения с MD3/iOS; паттерны обвязки
  из примеров; чужие компоненты в кадрах — «см. стенд X» (Slide toggle → Form-Field-Input;
  Timepicker → Select_DS; Chips-Input → Select_DS и т.д.).
- Пустые/черновые кадры — как на канве (пунктир/пометка), не додумываем; пометки страницы
  («в проработке», «скопирован из прошлого проекта») — в шапку и на стенд.
- Артефакты генератора (плашки «фон = цвет текста», белые подложки слотов, развёртка полос
  колонкой, русские имена классов и т.п.) — снимаются в `fixes.css`/обвязке; сами css не правим.
- ⭐ **Полоса над таблицей (table-header-actions) — всегда по ширине таблицы** (владелец, 14.10.2026):
  края полосы и таблицы совпадают; полоса и таблица стоят в общей обёртке по ширине содержимого
  (`.snap-set` — на стенде Table), ширину задаёт таблица; отступ полоса↔таблица — 8; контейнер таблицы
  не должен быть шире её рядов (иначе полоса «уезжает» за край — фиксированные ширины контейнеров не брать).
- ⭐ **Адаптив/мобильные виды — работают пальцем (тач)** (владелец, 15.10.2026: «это адаптив и работать будут
  пальцами, тач нажатия»): в адаптивных видах ховер-механики не проектируем (вид для тача; косяк ДС —
  sticky hover на тач, п. 26 журнала), состояния даются тач-нажатием. Далее: «возможно далее нужно будут
  применить паттерны и механики для адаптива и мобилы» — применяем по мере появления (журнал №186).

## 6. Подсказки ДС — смысл работы, находки, журнал (единая механика)

- ⭐ **Смысл работы — поиск недочётов** (слова владельца, 13.10.2026): собирая стенд (панель,
  витрину, пример), сверяем **Figma ↔ ДС (css, токены) ↔ сборку** и находим все расхождения —
  пробелы ДС, кривую выгрузку, невоспроизведённое. Каждая находка — **подсказка ДС**.
- ⭐ **Подсказки и отчёт — одно и то же** (владелец, 13.10.2026: «мы их назвали Подсказки ДС…
  это одно и то же, что ты выдаёшь в отчётах»). Находка живёт в трёх местах, везде — один
  **сквозной номер пункта журнала `Design-System/fixes.md`**:
  1. **На странице** — ОДИНАКОВЫЙ механизм у всех (владелец, 13.10.2026: «подсказки выводим
     одинаково… там кнопка была и метки»): кнопка «**Подсказки ДС · N**» + номерные метки у мест;
     клик по метке — всплывашка «№N. суть». У демо-стендов — `ds-review.js` в режиме «только подсказки»
     (`data-hints-only`) + реестр `layouts.js` рядом со стендом, кнопка — в плашке стенда
     (`[data-hints-host]`); у страниц-прототипов — тот же файл панелью ревью (бар, `?hints=1`).
     Перенимаем не оформление страниц, а механизм — кнопка + метки + номера журнала.
  2. **В коде** — у обхода метка «пробел ДС №N»; общий обход компонента — блоком в `../../fixes.css`.
  3. **В журнале `Design-System/fixes.md`** — полная запись: что не так → что доправить → где (Фигма / токены /
     CSS) + статус («открыт / обойдено в fixes.css / решено»); нумерация сквозная, номера не переиспользуются.
- **Формат находки** (в «Подсказках ДС» и в отчёте владельцу) — только два факта (правило владельца,
  13.10.2026): **что не сходится с Figma → что доделано самому** (обход/фикс на стенде).
  Пункты «что поменять в ДС» — содержание журнала, не отчёта.
- Пробел (нет класса/состояния/цвета/раскладки) → либо **обвязка стенда на токенах** + пометка
  «решить в ДС», либо **фикс в `../../fixes.css`**; в обоих случаях — **запись в `Design-System/fixes.md`**.
- Стенд ссылается на номер: в шапке-комментарии, в «Подсказках ДС» («Журнал №N») и в метках кода.
