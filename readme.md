# Дизайн-система iiko — рабочая папка

Здесь лежит ДС iiko: компоненты, токены и оба слоя системы.

Важно: это **два репозитория**. `DS` — сама дизайн-система: обе папки слоёв (`components-web` и `components-mobile` лежат внутри него), общие сборки (`molecules`, `organisms`) и подключатель `connect.js`. `Prototypes` (прототипы экранов) — **отдельный репозиторий**: клонируется **рядом** с папкой `DS`, а не внутрь неё (см. §2). Оба живут в организации **iiko-DS** (`https://github.com/iiko-DS`).

Правила работы, база знаний по дизайн-системе и прототипам, рецепты и скиллы для ИИ-агентов лежат отдельно — папка [`prototyping-guide`](https://github.com/iiko-DS/Prototypes/tree/main/prototyping-guide) в репозитории `Prototypes`. Этот readme — про состав репозитория и правила работы; всё остальное — там.

## Структура

```
DS/
├── components-web/          папка ДС: компоненты, токены, стили, спецификация
├── components-mobile/       папка ДС: мобильный слой ДС
├── organisms/            организмы приложения (шапка, меню) — общие блоки для прототипов
├── molecules/            молекулы — мелкие общие сборки (пока пусто; правила — в readme)
├── connect.js            подключатель прототипов: одна строка — стили ДС, иконки, шапка, меню
├── fixes.md              журнал косяков ДС: что чинить в ДС и где обойдено локально (номера, статусы)
├── pull.py               обновление репозиториев DS и Prototypes одной командой
└── readme.md             этот файл
```

Весь этот каталог — репозиторий `iiko-DS/DS`: обе папки слоёв ДС, общие сборки и подключатель. Рядом с ним лежит репозиторий `Prototypes` — прототипы экранов и база знаний.

Здесь же — `connect.js`, подключатель для страниц-прототипов: в страницу вставляется одна строка
`<script src="путь/до/DS/connect.js" defer></script>` — и сами приходят стили ДС, иконки, шапка
и боковое меню (страница может лежать где угодно; флаги `data-no-header`, `data-no-sidenav`,
`data-mobile`, `data-molecules` — в самом файле).

## Как начать работу

Подробно, с нуля — для дизайнера, который подключается впервые.

### 1. Что понадобится

- **Доступ в организацию iiko-DS** — его выдаёт владелец: `https://github.com/orgs/iiko-DS/people` → `Invite member`. Без приглашения приватные репозитории не клонируются.
- **Git** — чтобы склонировать репозитории и присылать правки. Проще всего поставить **GitHub Desktop** и войти в свой аккаунт: он сам разберётся с авторизацией, токены руками вводить не нужно.
- **Python 3** — только для одной короткой команды `pull.py` (обновление репозиториев). Сторонних пакетов ставить не нужно.
- Любой редактор, удобнее всего VS Code: `Файл → Открыть папку` и выбрать папку `DS` целиком — тогда видны обе папки слоёв ДС и общие сборки сразу.

Проверить Python:

```
python --version      # Windows
python3 --version     # macOS и Linux
```

Нужен ответ вида `Python 3.x.x`. Если команда не найдена — поставить Python с python.org (галочка «Add Python to PATH» на Windows) и перезапустить терминал.

### 2. Куда клонировать

`DS` клонируется **одной папкой** (её имя любое, в примере `DS`) — папки `components-web` и `components-mobile` лежат внутри. **Имена этих двух папок менять нельзя** — на них по относительным путям ссылаются прототипы.

```
mkdir DS
cd DS
git clone https://github.com/iiko-DS/DS.git .           # слои ДС и подключатель
cd ..
git clone https://github.com/iiko-DS/Prototypes.git  # прототипы и база знаний — рядом с папкой DS
```

Прототипы экранов (`Prototypes`) — **отдельный репозиторий**: если он нужен,
клонируйте его **рядом** с папкой `Design-System` (не внутрь) — прототипы подключают ДС по пути `../Design-System/…`.

В GitHub Desktop это то же самое без командной строки: `File → Clone repository → GitHub.com` —
склонировать `DS` (в папку `DS`) и `Prototypes` (рядом с ней).

Должно получиться так:

```
DS/
├── readme.md              этот файл
├── connect.js             подключатель страниц-прототипов
├── components-web/        компоненты, токены, стили (десктопный слой ДС)
├── components-mobile/     мобильный слой ДС
└── fixes.md               журнал косяков ДС

Prototypes/                 прототипы и база знаний (отдельный репозиторий рядом)
```

Репозитории приватные. Если какой-то не клонируется — нет доступа, попроси приглашение у владельца организации.

### 3. Короткие команды на каждый день

```
python pull.py     # обновить репозитории DS и Prototypes из организации
```

`pull.py` ничего не тронет, если в репозитории лежат незакоммиченные правки или ты сидишь в своей ветке: он об этом сообщит.

Новичку проще начать с короткой инструкции — [start-here.md](start-here.md): что поставить и какие команды выполнить.

## Как мы работаем вместе

Правило простое: **`main` — общая база, свои пробы — в своей ветке, в общее — через Pull Request.**

- **`main` — база для всех.** Это то, чем пользуются все: слои ДС, общие сборки, прототипы. Прямо в `main` не пишем.
- **Свои пробы — в своей ветке.** В GitHub Desktop: `Current Branch → New Branch`, имя вида `ivan/badge-fix`. В своей ветке можно делать что угодно: у остальных `main` остаётся чистым, и их `git pull` не ломается.
- **«Вот это стоит взять всем» — это Pull Request.** Когда проба получилась: `Push origin` → `Create Pull Request` в `main`. Видно, что именно меняется, можно обсудить в комментариях и влить. Так «важное и интересное» попадает в общую базу, а не переписывается руками.
- **Перед началом работы и после чужого PR — `git pull`** в `main`, чтобы база была свежая.

Почему не «копим локально, потом перенесём руками»: если держать несохранённые правки поверх `main`, первый же `git pull` из организации упрётся в «local changes would be overwritten», и разбирать это придётся по файлам. Ветка — это и есть «локально своё, в общее только важное», только без потери правок.

Ограничение, о котором стоит знать: на бесплатном плане **защита ветки в приватных репозиториях недоступна** (protected branches — только для публичных на Free, для приватных нужен платный план). Значит «в `main` только через Pull Request» — договорённость, а не настройка, которую нельзя обойти.

### Что коммитим, а что нет

- **Коммитим:** CSS компонентов, общие сборки (молекулы и организмы), прототипы.
- **Не коммитим:** секреты и служебный мусор — см. раздел «Что не коммитим» ниже.

### 4. Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `python: command not found` | Python не установлен или не в PATH. Установить с python.org, перезапустить терминал. На macOS/Linux пробовать `python3` |
| Репозиторий не клонируется | Нет доступа в организацию iiko-DS — попросить приглашение у владельца |
| `pull` ругается на local changes | Правки лежат в `main` вместо своей ветки — перенести их в ветку (`Current Branch → New Branch` переносит изменения) и вернуть `main` чистым |

## Где что править

- **CSS компонентов** — `components-web/components/…` (десктопный слой) и `components-mobile/components/…` (мобильный слой).
- **Общие сборки для прототипов** — `molecules/`, `organisms/`; подключение страниц — `connect.js`.
- **Прототипы экранов** — в отдельном репозитории `Prototypes` (клонируется рядом с папкой DS).
- **Журнал косяков ДС** — `fixes.md`: что чинить в ДС и где обойдено локально.

## Что не коммитим

- Секреты: `.env`, `.env.*`, `.vscode/mcp.json` (в нём токен Figma — для команды есть `.vscode/mcp.example.json`).
- Кэш Python: `__pycache__/`, `*.pyc`.
- Разовые проверочные материалы: снимки экрана, пробы, временные страницы замеров.
